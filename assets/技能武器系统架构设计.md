# 技能 & 武器系统架构设计

---

## 1. 现有系统梳理

| 系统 | 文件 | 职责 |
|------|------|------|
| 角色控制 | `第一关/人物/action.ts` | 移动、跳跃、攻击（J键），攻击属性硬编码 |
| 角色属性 | `第一关/人物/PlayerStats.ts` | 血量/魔力/经验/等级，受击扣血 |
| 背包 | `第一关/功能及按钮/BagManager.ts` | 物品存储、使用药水，只存不卖 |
| 宝箱 | `第一关/功能及按钮/TreasureChest.ts` | 随机掉落物品（金币/药水→进背包） |
| 关卡数据 | `登录及关卡选择脚本/LevelDataManager.ts` | localStorage 存关卡解锁/星级 |
| 登录 | `登录及关卡选择脚本/LoginManager.ts` | 有角色/设置等按钮但未实现 |

**现有关键问题：**

- 没有金币货币系统（宝箱掉的金币只是背包物品，不可消费）
- 攻击属性 `attackDamage`、`attackRange`、`attackCD` 都硬编码在 `action.ts` 里
- `PlayerStats` 只在关卡内有效，没有跨场景的持久数据

## 2. 三层架构总览

```
┌────────────────────────────────────────────┐
│  表现层 (UI)                                │
│  ShopPanel.ts    商店面板（购买/装备）        │
│  SkillBarUI.ts   技能栏（显示冷却/快捷键）     │
│  WeaponSlotUI.ts 武器槽（显示当前武器）       │
└──────────────┬─────────────────────────────┘
               │ 读写
┌──────────────▼─────────────────────────────┐
│  逻辑层 (Manager)                           │
│  SkillManager.ts   技能执行（挂玩家节点）     │
│  WeaponManager.ts  武器切换（挂玩家节点）     │
└──────────────┬─────────────────────────────┘
               │ 读写
┌──────────────▼─────────────────────────────┐
│  数据层 (Singleton + localStorage)          │
│  PlayerDataManager.ts                      │
│  - 金币数量                                  │
│  - 已解锁技能列表                             │
│  - 已解锁武器列表                             │
│  - 当前装备的武器ID                           │
│  - 当前装备的技能ID（1-4槽位）                 │
└────────────────────────────────────────────┘
```

**每层互不干扰现有功能**，对已有代码的改动量降到最低。

## 3. 数据层 — `PlayerDataManager.ts`

> 全局单例，跨场景持久化，底层用 `localStorage`。

### 数据结构

```typescript
{
  gold: 0,                          // 金币
  weapons: {
    unlocked: ['sword'],            // 已解锁的武器ID列表
    equipped: 'sword',              // 当前装备的武器ID
  },
  skills: {
    unlocked: [],                   // 已解锁的技能ID列表
    equipped: [null, null, null, null],  // 4个技能槽，null表示空
  }
}
```

### 对外方法

| 方法 | 说明 |
|------|------|
| `getGold(): number` | 获取金币余额 |
| `addGold(n: number)` | 增加金币 |
| `spendGold(n: number): boolean` | 消费金币，余额不足返回 false |
| `isWeaponUnlocked(id): boolean` | 武器是否已解锁 |
| `unlockWeapon(id)` | 解锁武器 |
| `equipWeapon(id)` | 装备武器 |
| `getEquippedWeapon(): WeaponConfig` | 获取当前装备的武器配置 |
| `isSkillUnlocked(id): boolean` | 技能是否已解锁 |
| `unlockSkill(id)` | 解锁技能 |
| `equipSkill(slot, id)` | 将技能装备到指定槽位 (0-3) |
| `getEquippedSkills(): SkillConfig[]` | 获取当前装备的技能配置数组 |

## 4. 武器系统

### 武器配置表

```typescript
const WEAPONS = {
  sword:      { id:'sword',      name:'铁剑',   damage:1,  range:200, speed:1.0,  price:0 },    // 默认
  spear:      { id:'spear',      name:'长枪',   damage:2,  range:280, speed:0.8,  price:50 },
  dagger:     { id:'dagger',     name:'匕首',   damage:1,  range:120, speed:1.8,  price:30 },
  greatsword: { id:'greatsword', name:'巨剑',   damage:3,  range:220, speed:0.5,  price:100 },
};
```

| 字段 | 说明 |
|------|------|
| `damage` | 每次攻击的基础伤害值 |
| `range` | 攻击检测范围（像素） |
| `speed` | 攻击速度倍率，1.0=默认，1.8=快1.8倍 |
| `price` | 商店购买价格（0=初始拥有） |

### `WeaponManager.ts` — 挂玩家节点

```typescript
// 从 PlayerDataManager 读取装备的武器配置
// 对外暴露：
getAttackDamage(): number   // 当前武器伤害
getAttackRange(): number    // 当前武器范围
getAttackCD(): number       // 当前武器冷却
```

### 对 `action.ts` 的改动（最小化）

```typescript
// ── 改前（硬编码）──
attackDamage: number = 1;
attackRange: number = 200;
attackCD: number = 0.5;

// ── 改后（动态读取）──
// 这些属性保留默认值作为 fallback
// 在 tryAttack() 中从 WeaponManager 读取覆盖：
const weaponMgr = this.getComponent(WeaponManager);
const dmg = weaponMgr ? weaponMgr.getAttackDamage() : this.attackDamage;
const range = weaponMgr ? weaponMgr.getAttackRange() : this.attackRange;
```

> **不改武器时跟原来一模一样，换了武器属性自动变化。** 原有代码逻辑不动。

## 5. 技能系统

### 技能配置表

```typescript
const SKILLS = {
  fireball:  { id:'fireball',  name:'火球术', manaCost:15, cooldown:3,  type:'projectile',   damage:5,  price:30 },
  heal:      { id:'heal',      name:'治愈术', manaCost:20, cooldown:8,  type:'selfHeal',     heal:30,  price:40 },
  whirlwind: { id:'whirlwind', name:'旋风斩', manaCost:25, cooldown:6,  type:'aoe',          damage:4,  range:300, price:60 },
  shield:    { id:'shield',    name:'护盾',   manaCost:30, cooldown:12, type:'buff',         duration:5, price:50 },
};
```

| 字段 | 说明 |
|------|------|
| `manaCost` | 释放所需魔力 |
| `cooldown` | 冷却时间（秒） |
| `type` | `projectile`（发射物）、`selfHeal`（自愈）、`aoe`（范围伤害）、`buff`（增益） |
| `price` | 商店购买价格 |

### `SkillManager.ts` — 挂玩家节点

```
核心逻辑：
1. 监听按键 1/2/3/4（对应4个技能槽）
2. 检查 ①该槽位是否装备了技能 ②技能是否已解锁 ③魔力是否足够 ④是否在冷却中
3. 满足条件 → 扣除魔力 + 执行技能效果 + 进入冷却
4. 不满足 → 不执行（可选：显示提示）
```

### 技能类型实现

| type | 效果 |
|------|------|
| `projectile` | 朝玩家朝向生成弹幕节点，飞行碰撞敌人造成伤害 |
| `selfHeal` | 直接调用 `PlayerStats.heal(value)` |
| `aoe` | 以玩家为中心，检测范围内所有敌人并调用 `takeDamage` |
| `buff` | 给玩家加临时 Buff（如护盾吸收伤害、攻击力翻倍），持续 N 秒 |

### 对现有系统的改动

**零。** 技能是纯新增系统，不影响 J 键攻击和 WASD 移动。

## 6. 商店系统 — `ShopPanel.ts`

> 类似 `UIManager` 的面板模式，挂 Canvas 节点。

### UI 结构

```
┌──────────────────────────────────┐
│  🪙 金币: 120        [✕ 关闭]    │
├──────────────────────────────────┤
│  [🗡️ 武器]  [✨ 技能]    ← Tab  │
├──────────────────────────────────┤
│  ┌────────┐ ┌────────┐          │
│  │ 图标    │ │ 图标    │          │
│  │ 长枪    │ │ 巨剑    │          │
│  │ 伤害+2  │ │ 伤害+3  │          │
│  │ 范围280 │ │ 范围220 │          │
│  │ [50金币]│ │ [已装备] │          │
│  └────────┘ └────────┘          │
│  ┌────────┐ ┌────────┐          │
│  │ 图标    │ │ 图标    │          │
│  │ 匕首    │ │ ...    │          │
│  │ ...    │ │        │          │
│  └────────┘ └────────┘          │
└──────────────────────────────────┘
```

### 交互逻辑

```
点击物品：
  ├─ 未解锁 + 金币足够 → 确认购买 → 扣除金币 → 解锁
  ├─ 未解锁 + 金币不足 → 提示金币不足
  ├─ 已解锁 + 未装备 → 装备该武器/技能
  └─ 已装备 → 显示"使用中"
```

### 访问入口

- 关卡选择界面放一个「商店」按钮
- 游戏内按 B 键呼出商店面板

| 文件 | 位置 | 作用 |
|------|------|------|
| `PlayerDataManager.ts` | `scripts/data/` | 全局持久数据（金币/解锁/装备状态），localStorage |

| `SkillManager.ts` | 挂玩家节点 | 技能按键监听、条件检查、执行、冷却管理 |
| `ShopPanel.ts` | 挂 Canvas | 商店 UI（浏览、购买、装备武器和技能） |

| 文件 | 改动 | 程度 |
|------|------|------|
| `action.ts` | `tryAttack()` 中从 `WeaponManager` 动态读伤害/范围/CD，不再硬编码 | 🟡 小 |
| `PlayerStats.ts` | 无需改动 | 🟢 零 |
| 其他所有文件 | 无需改动 | 🟢 零 |

## 9. 设计原则

1. **不破坏已有功能** — 攻击/移动/受击全部保持不变，新功能是增量叠加
2. **数据统一管理** — 金币和装备状态在 `PlayerDataManager` 一处读写
3. **配置与逻辑分离** — 武器/技能数值放在 Config 常量里，改数值不用改逻辑
4. **每关复用** — `WeaponManager` 和 `SkillManager` 挂在玩家预制体上，所有关卡自动生效
5. **商店独立** — 商店面板与游戏逻辑解耦，可放在关卡选择场景或游戏内呼出
6. **向后兼容** — 所有新组件如果不存在，`action.ts` 使用原有硬编码默认值
